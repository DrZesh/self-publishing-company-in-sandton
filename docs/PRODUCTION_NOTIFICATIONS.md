# Creative Books service workflows

The production catalogue now follows the attached specification exactly: Printing has 8 stages, Book Cover Design 6, Typesetting 3 and Book Editing 9. The 26 default subject lines and messages are stored in `cb_service_email_templates` and editable at `/admin/billing/templates`, also linked from the existing Email Templates settings page. The source fixture is `supabase/fixtures/service-workflows.json`.

Each selected service has an independent progress row, current stage, completed checks, skipped stages and revision number. Package stages can be skipped without adding unpaid rounds. Existing project identifiers, financial status, payment records and original completion flags are preserved. The full earlier production state is archived in `cb_projects.legacy_production`; old labels are mapped to the closest new stage by meaning. New intermediary stages are not falsely marked complete. The migration does not enqueue historical client emails.

Staff stage transitions queue the matching saved template once. Saving unrelated fields, refreshing, updating template wording and migrating do not send stage mail. Stable transition keys, immutable first-attempt snapshots, provider idempotency, leases and safe retries remain in place. A deliberate resend is a new explicit staff action with its own request ID. Project history records the service, stage, recipient, provider submission time and status.

The existing branded logo, rainbow header, copper colours and footer are reused. First names and book titles populate automatically, with `Hi there,` and `your book` fallbacks. Book titles can be corrected on the project and are initially sourced from a linked CRM contact or quote subject. The ready-for-collection printing message changes when the account is fully settled. Where money remains outstanding, an assigned internal task is created to send the remaining-balance invoice; the stage email does not claim the invoice was already sent.

The project portal is `/portal/p/:token`. It displays each selected service, production readiness, completed and skipped stages, released files, review delivery status and client review approval separately. The accepted-quote screen links to it. General legacy portal tokens can also link to the same client's billing projects; project-restricted legacy tokens do not gain access to additional projects. Portal pages are excluded from indexing and use a no-referrer policy.

Author review requires selected private review files or a staff-confirmed client-accessible HTTPS link and appropriate instructions. Missing materials leave the stage saved and the email explicitly blocked/pending. Saving the required review settings releases a never-attempted pending action email safely. Previously attempted snapshots are not silently rewritten. Word Track Changes instructions are included only when staff confirm they are used; the configured editor name is Mac. Uploaded documents are preserved, so staff must supply the agreed, correctly attributed files.

Completion of cover concepts, typesetting or editing creates an assigned delivery task. It does not release files, mark actual delivery, approve print-ready artwork or grant client approval. An intentional delivery requires selected agreed files and review instructions, and can be previewed before staff send it. Only that delivery email's provider acknowledgement updates its delivery record and completes the delivery task. It does not guarantee inbox receipt or mark client approval. Client file access requests are recorded separately.

Project files use the private `cb-project-deliverables` bucket, limited to 50 MB per file. The file endpoint checks the project capability and release state before creating a two-minute download link or redirecting to the confirmed secure URL. Only explicitly released resources appear in the client portal. Clients can submit author feedback and a feedback-document link; the assigned current staff member receives an email and CRM alert. General business email is the fallback when no eligible staff member is assigned. Review approval is a separate explicit client action, not automatic print approval.

Validation uses synthetic local records, mocked transports and test recipients. The automated suite covers the 26 exact stage transitions, placeholders, branded previews, editable templates, duplicate prevention, independent multi-service progress, safe failures, skipped editing stages, review-file requirements, delivery tasks, payment-dependent printing wording, access boundaries and separate delivery / approval states. Production build and targeted lint checks are required before release.

No new external credentials are required. Operational preparation: select purchased services, set a book title and assigned team member, then upload the correct review/delivery files and instructions when ready. Existing acceptance alerts to info@creativebooks.co.za and draubreyzesh@gmail.com remain active.

Review approval is also recorded on the specific delivery. A new intentional delivery reopens its internal delivery task and clears the current approval until the client reviews the latest sent delivery. Earlier delivery approvals remain in the audit history.

Marketing analytics and the SalesIQ widget are not initialised on private portal or CRM entry pages. Public marketing pages retain the existing integrations.
